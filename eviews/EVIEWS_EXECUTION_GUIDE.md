# EViews execution guide

**Status:** EViews was **not** available in the environment where this project was built. Every result in this
repository was computed in Python (`statsmodels 0.15`, `arch 9`) by `scripts/03_estimate.py`, and every result is
labelled `computed_python_pending_eviews` until it has been reproduced in EViews. This guide explains how to run
the EViews workflow, which checks to make, and how to promote the results to `verified`.

Tested assumptions: EViews 10 or later (ARDL estimator, `@runpath`, `table.save(t=csv)`). EViews 9 has the ARDL
estimator but some menu names differ.

---

## 1. Files

| File | What it does |
|---|---|
| `00_master.prg` | Runs everything below in order and saves `falling_rupee.wf1` |
| `01_import.prg` | Creates a monthly workfile 2015M01–2025M12 and imports `data/processed/estimation_sample.xlsx` (sheet `data`) |
| `02_descriptives_unitroots.prg` | Descriptive statistics, correlation matrices, ADF (AIC & SIC), PP and KPSS on levels, 1st and 2nd differences |
| `03_ols.prg` | Baseline OLS (plain and HAC), VIF, Breusch-Godfrey, BPG, RESET, Engle-Granger, first-difference OLS |
| `04_ardl.prg` | Linear ARDL: native estimator + explicit conditional-ECM replication, bounds Wald test, long-run Wald, diagnostics, CUSUM/CUSUMSQ |
| `05_nardl.prg` | Nonlinear ARDL with LEXR_POS / LEXR_NEG, same outputs + long-run and impact symmetry Wald tests |
| `06_robustness.prg` | The 13 robustness specifications (conditional-ECM route) with bounds and symmetry tests |
| `output/` | Written by the programs: coefficient CSVs and stability graphs |

The programs are generated by `scripts/06_write_eviews.py` from the specification that was actually estimated, so the
lag orders and regressor order always match the website. Do not edit them by hand; re-generate them instead.

## 2. Run

1. Copy or clone the whole repository (the programs use relative paths: `..\data\processed\…`).
2. In EViews: **File ▸ Open ▸ Program…** → `eviews/00_master.prg` → **Run**.
3. Confirm in the workfile: scalar `chk_nobs = 132`, scalar `chk_ps_max ≈ 0` (partial sums reconstruct ln EXR).

If the `import` line fails on your EViews version, open `data/processed/estimation_sample.xlsx` via
**File ▸ Open ▸ Foreign Data as Workfile**, set frequency *Monthly* starting *2015M01*, save as `falling_rupee.wf1`,
then run programs `02`–`06` individually.

## 3. Native ARDL route — what to check

Programs `04` and `05` estimate `eq_ardl_main_native` and `eq_nardl_main_native` with automatic lag selection
(maximum 4 lags for the dependent variable and regressors, Akaike criterion, 11 seasonal dummies as fixed regressors).

* **Trend specification:** it must be *Constant (unrestricted)* — PSS case III. If your version's `trend=` keyword
  differs, open the equation, **Estimate ▸ Options ▸ Trend specification ▸ Constant (unrestricted)**.
* **Selected model** should be `ARDL(2,1,3,2)` (linear) and `ARDL(1,0,1,0,2)` (NARDL).
* Then **View ▸ Coefficient Diagnostics ▸ Long Run Form and Bounds Test** and compare:

| Quantity | ARDL(2,1,3,2) — Python | NARDL(1,0,1,0,2) — Python |
|---|---|---|
| Bounds F-statistic (k) | 7.537 (k = 3) | 5.356 (k = 4) |
| t-statistic on LFOODCPI(-1) | −3.832 | −2.393 |
| CointEq / ρ | −0.1197 | −0.0987 |
| Long-run LEXR / LEXR_POS | 0.6398 (s.e. 0.2187) | 0.5298 (s.e. 0.2593) |
| Long-run LEXR_NEG | — | 1.1837 (s.e. 1.1151) |
| Long-run LGFOOD | 0.6061 (s.e. 0.1899) | 0.6533 (s.e. 0.3511) |
| Long-run LTRANSCPI | 0.2056 (s.e. 0.2233) | 0.4959 (s.e. 0.2268) |

EViews prints PSS asymptotic and finite-sample (Narayan-type) bounds beside the F-statistic. Our Python run reports
PSS (2001) asymptotic case III bounds and its own 20,000-draw Monte Carlo finite-sample bounds (n = 128); both should
lead to the same decision.

## 4. Explicit OLS route — exact replication

`eq_*_lev` (levels ARDL) and `eq_*_cec` (conditional error-correction form) are estimated by OLS on 2015M05–2025M12
with exactly the Python regressor order. Their coefficient tables are written to `eviews/output/*.csv`.

* `tb_*_bounds` — Wald F on all level terms = the PSS F-statistic.
* `tb_*_lr_<var>` — Wald on `-c(i)/c(2) = 0`: the "Value" and "Std. Err." are the long-run coefficient and its
  delta-method standard error.
* `tb_nardl_lrsym` — long-run symmetry, Wald χ² on `c(3)/c(2) = c(4)/c(2)` (Python: χ² = 0.466, p = 0.495).
* `tb_nardl_lrsym_lin` — the linear form θ⁺ = θ⁻ (Python: F = 0.769, p = 0.382).
* `tb_nardl_impact` — impact symmetry β⁺₀ = β⁻₀ in the levels ARDL (Python: F = 5.350, p = 0.023).
* Diagnostics: `tb_*_bg2/bg12/bpg/white/arch1/arch12/reset/jb`; stability graphs `gr_*_cusum`, `gr_*_cusumsq`.

## 5. Promote results to "verified"

```bash
python scripts/07_compare_eviews.py     # compares eviews/output/*.csv with the Python fits (rtol 1e-4)
python scripts/05_build_registry.py     # propagates 'verified' to data/research/*.json
```

Commit `research/eviews_verification.json`, `eviews/output/` and `data/research/`, then redeploy: the website's
status badges switch from "Python estimate · EViews pending" to "Verified in EViews" automatically.

## 6. Known differences to expect

* **White test:** EViews' default omits cross terms; so does `scripts/03_estimate.py`. If you tick *Include White
  cross terms* the statistic changes.
* **KPSS / PP bandwidths:** EViews uses Newey-West Bartlett bandwidths by default; Python's `arch`/`statsmodels`
  choices are close but test statistics can differ in the second decimal. Integration-order decisions should not change.
* **CUSUM of squares bounds:** EViews uses tabulated Durbin (1969) critical values; Python uses a Monte Carlo bound.
* **Dynamic multipliers** are not produced by the built-in ARDL view; they come from `scripts/ardl_engine.py`.
